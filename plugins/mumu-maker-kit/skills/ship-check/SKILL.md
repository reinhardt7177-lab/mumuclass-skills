# 마무리 루틴 — 올리고, 배포하고, 운영에서 확인하고, 주소까지

"배포했어요"는 운영 주소에서 새 버전을 눈으로 확인한 뒤에만 말한다. 사용자가 "주소 주세요"라고 하기 전에 주소를 준다.

## 1. 올리기 전 점검
- `git status`로 바뀐 파일을 본다. **내가 바꾸지 않은 파일(다른 사람이나 다른 AI의 작업)은 커밋에 넣지 않는다.** 섞여 있으면 사용자에게 알린다.
- 비밀값 검사: API 키, 토큰, 비밀번호, 학생 개인정보가 코드·커밋에 들어가지 않았는지 확인한다. `.env`가 `.gitignore`에 있는지 본다.
- 빌드와 테스트(있으면)를 돌린다. 실패하면 배포하지 않는다.

## 2. 커밋·푸시
- 그 저장소의 커밋 메시지 습관(한국어, 형식)을 따른다.
- 기본 브랜치에 바로 올리는 저장소인지, PR을 쓰는 저장소인지 확인한다.

## 3. 배포
- 그 앱이 쓰는 배포처를 따른다(README, package.json 스크립트, wrangler·vercel 설정 확인). 배포처를 마음대로 바꾸지 않는다.
- 배포 로그에서 주소와 버전 ID를 확인한다.

## 4. 운영 주소에서 확인 (빠뜨리지 않기)
- 운영 주소를 열어 **이번에 바꾼 내용이 실제로 보이는지** 확인한다. 화면으로 보거나, 배포된 JS·HTML에서 바뀐 문구를 찾는다.
- 옛 버전이 뜨면: 빌드 결과물이 새것인지, 캐시(브라우저·CDN·서비스 워커), 배포된 프로젝트·도메인 연결이 맞는지 차례로 본다.
- 주요 화면이 열리는지, 기존 기능이 사라지지 않았는지 한 번 훑는다.

## 5. 보고
- 운영 주소(클릭할 수 있는 링크), 커밋 한 줄, 확인한 것, 확인 못 한 것
- 필요하면 공유용 썸네일·OG 이미지·소개글까지 챙길지 묻는다
