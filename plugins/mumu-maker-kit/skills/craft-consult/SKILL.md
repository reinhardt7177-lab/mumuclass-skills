# 만들기 전에 상담 먼저 — 쉬운 길 금지

이 사용자는 **트렌드에 민감하고 디테일에 괴로울 정도로 집착**한다. 가장 견디기 힘들어하는 것은 AI가 상담 없이 **이미 학습된 가장 쉬운 방법**으로 결과물을 뽑는 것이다. 앱 디자인, 게임, 모션, 에셋 모두 마찬가지다. 그렇게 하면 디자인이 틀어지고 디테일이 무너진다.

## 절차

### 1. 요청 파악 (모르면 한 번에 묻고, 짐작되면 확인)
- 무엇을, 누구에게(학년·교사·일반), 어디서(웹·모바일·태블릿·전자칠판·영상) 쓰나
- 핵심 행동 하나: 사용자가 이 화면·게임에서 반드시 해야 하는 것
- 레퍼런스(링크, 게임, 앱, 이미지)와 원하는 느낌
- 기존 앱이면 지켜야 할 것: 스택, 데이터, 기능, 자산

### 2. 최신 사례 조사
웹에서 최근 3~6개월의 실제 사례를 날짜·출처·링크와 함께 찾는다. 조사하지 못했으면 했다고 말하지 않는다.

### 3. 방향 3개 + 추천 1개
분야별 선택지 사전에서 조합한다.
- 앱·웹 화면: `references/app-ui.md`
- 게임: `references/game.md`
- 모션·연출: `references/motion.md`
- 이미지·3D 에셋: `references/asset.md`

각 방향에 **콘셉트 / 풍 / 구조·레이아웃(게임은 핵심 루프) / 제작 방법·기술 / 장단점**을 적는다. 세 방향은 **구조부터 달라야 한다**(색만 바꾼 변주는 안 됨). 추천 하나를 이유와 함께 고른다. 쉬운 방법을 추천할 때는 그게 왜 이 경우에 최선인지 근거를 댄다.

### 4. 구체 기획 (고른 뒤)
- 화면: 그리드, 간격 단위, 타이포 스케일, 팔레트, 컴포넌트 상태, 모바일 배치
- 게임: 핵심 루프, 조작, 손맛 목록, 난이도 곡선, 에셋 목록
- 모션: 비트별 스토리보드와 easing
- 가능하면 무드보드나 시각 시안을 함께 보여 준다.

### 5. 시안 → 승인 → 제작
핵심 화면 1장, 게임 한 판, 모션 3~5초처럼 작은 시안을 먼저 보여 주고 승인을 받은 뒤 전체를 만든다. 이번 작업에서 이미 승인한 기획은 이어서 적용하고 같은 승인을 반복해서 묻지 않는다.

### 6. 보여 주기 전 검수 + "쉬운 길 신고"
- 실제 화면 스크린샷으로 `detail-qa` 스킬의 10개 항목을 모두 확인하고, 걸리면 고친 뒤에 보여 준다.
- **쉬운 길 신고**: 결과를 보고할 때 "기본값이나 쉬운 방법으로 처리한 부분"을 스스로 나열한다. 예: "버튼 호버는 기본 scale로 둠, 배경은 단색 그라디언트로 임시 처리". 숨기지 않는다. 사용자는 숨긴 지름길을 발견하는 것을 가장 싫어한다.

## 분야 공통 금지 (쉬운 길 목록)
- 상담 없이 바로 만들기, 방향 하나만 내놓기
- 이전 앱의 구조·폰트·레이아웃·모션을 복붙하기
- 코드·SVG·CSS 도형·이모지로 그림 대신하기 (이미지 에셋을 쓴다)
- 템플릿 기본값을 그대로 두기: 기본 컴포넌트 라이브러리 스타일, 가운데 정렬 히어로 + 카드 3개, 모든 요소에 같은 둥근 모서리·그림자
- 모든 움직임에 같은 duration·easing 쓰기, 스크롤하면 아래에서 페이드업
- 게임에서 손맛 없이 판정만 있는 조작(이펙트·소리·히트스톱 없음)
- 검수 없이 "완료" 보고
