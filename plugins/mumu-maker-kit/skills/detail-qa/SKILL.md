# 디테일 검수 — 보여 주기 전에 반드시

작은 어긋남 하나도 넘어가지 못하는 사용자를 위한 검수다. 실제 화면을 스크린샷으로 찍어 아래 10개 항목을 하나씩 확인하고, 하나라도 걸리면 **고친 뒤에** 보여 준다. "대충 맞음"은 실패다.

## 절차
1. 결과물을 실제로 띄운다(브라우저, 게임 실행, 렌더링). 코드만 보고 판단하지 않는다.
2. 데스크톱 → 태블릿 → 모바일(→ 전자칠판 가로) 순서로 스크린샷을 찍는다.
3. 아래 항목을 확대해서 본다. 걸린 곳을 목록으로 적는다.
4. 고치고, 다시 찍어서 확인한다.
5. 결과를 한 줄로 보고한다. 예: "정렬·간격·대비 확인 완료, 모바일 1곳 수정함"

## 10개 항목
| 항목 | 확인할 것 |
|---|---|
| 정렬 | 같은 줄·열이 같은 기준선에 맞는가. 아이콘과 글자의 세로 중심, 버튼 안 글자 중앙, 눈으로 봤을 때의 정렬(광학 정렬) |
| 간격 | 정해진 간격 단위(4/8px 등)를 일관되게 쓰는가. 같은 관계는 같은 간격, 묶을 것은 가깝게·나눌 것은 멀게 |
| 균형 | 좌우·상하 시각적 무게가 맞는가. 한쪽만 비거나 몰리지 않는가. 빈 공간은 의도된 것인가 |
| 위계 | 제목 → 부제 → 본문 → 보조의 크기·굵기·색 차이가 분명한가. 가장 중요한 것이 먼저 보이는가 |
| 일관성 | 같은 역할의 버튼·카드·모서리·그림자·아이콘 크기·선 굵기가 같은가. 폰트는 2~3종 이내인가 |
| 타이포 | 행간·자간·줄 길이. 한 글자만 다음 줄로 넘어가거나 단어가 어색하게 끊기지 않는가 |
| 색·대비 | 팔레트 안에서만 쓰는가. 작은 글씨 대비가 4.5:1 이상인가 |
| 에셋 | 비율·해상도·화풍·빛 방향이 맞는가. 흐림, 늘어남, 잘림, 공중에 뜬 오브젝트가 없는가 |
| 반응형 | 모바일·태블릿·전자칠판 가로에서도 위 항목이 지켜지는가. 실제 문구·글꼴로 줄바꿈을 확인했는가 |
| 상태 | 오버·누름·비활성·로딩·빈 화면·오류 상태까지 디자인돼 있는가 |

## 게임이라면 추가로
- 조작: 끼임, 떨림, 입력 지연이 없는가
- 손맛: 타격감, 이펙트, 효과음, 히트스톱이 있는가
- 진행: 막히는 판이 없는가, 정답이 먼저 보이지 않는가

## 보고 형식
- 확인한 항목과 고친 곳을 짧게
- **쉬운 길 신고**: 기본값이나 임시로 처리한 부분이 남아 있으면 숨기지 말고 적는다
- 확인하지 못한 기기·상태가 있으면 "확인 못 함"이라고 적는다
